1What gets installed

Medical HRMS is one Frappe app, medical_hrms. It adds the college's HR processes on top of the standard Frappe HR (HRMS) app, and the Jameah views the Ministry's data agent reads. The standard apps are not modified.

PartWhat it gives the college
HR PortalOne page for HR: requests waiting for a decision, leave setup check and sick leave, recruitment, Ministry data, academic presence (/app/hr-dashboard).
Employee PortalSelf-service for every employee: 11 request types, the leave flow (plan, apply, return), balances and monthly limits (/app/employee-dashboard).
RequestsPermission, Remote Work, Salary Certificate, Overtime pre-approval, Training, Children Medical Allowance, Company Car, Employee Data Update, Leave Plan, Leave Return, Contract Renewal (HR only), Medical Licence.
LeaveEditable starter leave types and policies (annual 21 / 30 days), sick leave in 3 pay stages with its own sick year, monthly half-day and work-from-home limits.
RecruitmentJob Application Links, the public application form, review, and Create Employee (with login and, for academic roles, Instructor / Academic Advisor / Head of Department records).
Ministry codes9,867 official Ministry lookup codes, loaded on every migrate, used on Employee and applicant fields.
Jameah views23 read-only database views in the Ministry's format: Employees 5, Faculty 8, Students 10, with a Data Check page, a Code Map and an independent verification.
Academic presenceFaculty and proctor schedules, students on campus per hour, faculty after 4 PM.

2Before you start

  • A Frappe v15 bench with these apps installed on the site: frappe, erpnext, hrms, education.
  • MariaDB, Redis and Node (as for any Frappe bench). Medical HRMS needs no extra packages.
  • Workers running for the short, default and long queues, and the scheduler enabled. The Jameah academic figures are rebuilt every hour on the long queue.
  • Access to the GitHub repository phpdevpro/edu-alriyada-hrm. The branch to install is develop.
  • A backup of the site before you install or update: bench --site <site> backup --with-files.
The education app must be currentThe Ministry GPA and credit hours use the college's official calculation that comes with the latest education app (master branch). Update it on the server in the same deployment.

3Install on a new site

3.1 Install the app

Run these commands as the bench user, in the bench folder. Replace <site> with the site name.

cd ~/frappe-bench
bench get-app git@github.com:phpdevpro/edu-alriyada-hrm.git --branch develop
bench --site <site> install-app medical_hrms
bench --site <site> migrate
bench build --app medical_hrms
bench --site <site> clear-cache
bench restart

The app folder must end up as apps/medical_hrms, and sites/apps.txt must list each app on its own line (see Troubleshooting).

Read the migrate outputIt must finish without a Traceback. The last part rebuilds the Jameah academic figures and takes a few minutes. If it prints a line starting with Kept (they hold data ...), send that line to the developer.

3.2 What migrate sets up

Every migrate runs the app's setup steps, so a new site and an updated site end up the same. Nothing has to be run by hand.

StepWhat it does
Ministry codesLoads or updates the official Ministry lookup codes (Jameah Ministry Code).
Ministry fieldsAdds the Ministry and Jameah fields and tables to Employee and Instructor (identity, nationality, job rank, qualifications, experience, ...).
JameahCreates the Jameah doctypes and settings, refreshes the Code Map, creates the 23 views and rebuilds the academic figures.
HR permissionsGives HR roles the access their pages need (for example read on Company, Holiday List, Instructor).
Employee Self ServiceCreates the employees' workspace.
Leave starter recordsCreates the leave types (annual, Sick Leave 1 / 2 / 3, unpaid) and draft policies if they are missing. Existing records and HR's changes are kept.
Monthly limits, presenceAdds the HR Settings fields for monthly half-day / work-from-home limits and for academic presence.
PatchesOne-time data changes listed in patches.txt (for example the sick-leave renaming).
Do not run the old setup scriptsEarlier notes listed scripts such as configure_hrm_request_governance, quick_grant_hr_permissions and apply_hr_workspace_layout. Do not run them: the doctypes now carry their own permissions, and configure_hrm_request_governance would replace them.

4Update an existing server

  1. Back up the site: bench --site <site> backup --with-files.
  2. Get the new code: 
    cd ~/frappe-bench/apps/medical_hrms
git fetch origin
git checkout develop
git pull --ff-only origin develop
  3. Update the education app to its current master in the same deployment (see section 2).
  4. Apply it: 
    cd ~/frappe-bench
bench --site <site> migrate
bench build --app medical_hrms
bench --site <site> clear-cache
bench restart
  5. Run the checks in section 5.
TimingThe hourly Jameah refresh makes pages slower for a few minutes while it runs. A migrate never fails because of it any more (only one refresh runs at a time), but schedule updates outside busy hours.

6First-time setup

Done once by the system owner (HR Manager or System Manager) after the first installation, and checked at the start of every leave year.

6.2 Company and e-mail

  • Check the Company record of the college (Al Riyada College): default holiday list (section 6.3) and the company e-mail domain.
  • Academic hires must use their official college e-mail (@alriyada.edu.sa) as Company Email; the Create Employee dialog asks for it.
  • Open Email Account Notifications, enter its password again and save, then send a test e-mail. Until this works the system cannot send e-mails.

6.3 Leave, in this order

The HR Portal has a Leave section with a Leave setup check per company and the yearly setup steps in order. Work through the steps until every line of the check is green.

  1. Leave Period: create this year's leave period for the company and tick Is Active. Migrate creates an inactive starter period; check its dates and activate it.
  2. Holiday List: enter the official holidays and weekends for the year and set it as the company's default holiday list.
  3. Leave Policy: review the draft policies (annual leave 21 days, annual leave 30 days for five or more years of service, and the Sick Leave policy) and submit the ones the college uses.
  4. Leave Control Panel: assign the annual leave policy to the employees together. This gives them their balance.
  5. Leave Approvers: set who approves leave, on each Department (Leave Approvers table) or on each Employee.
  6. Monthly Limits: HR Settings → Employee Monthly Limits (section 6.5).
Until this is done, employees cannot apply for leaveAn employee with no annual leave assigned sees "No leave to apply for yet". Check the Leave setup check first when someone reports a leave problem.

6.4 Sick leave

Sick leave is separate from annual leave and follows the Saudi Labour Law: Sick Leave 1 30 days full pay, then Sick Leave 2 60 days at 75% pay, then Sick Leave 3 30 days unpaid, within one sick year that starts on the employee's first sick day.

  1. Submit the policy Medical HRMS - Sick Leave (3 Pay Stages, Separate Sick Year). Finance checks the 75% pay on a salary slip.
  2. On an employee's first sick day, HR opens HR Portal → Leave → Start Sick Leave Year, picks the employee and the first sick day. This creates their Sick Leave 1 and 2 balances for one year; annual leave is not touched.
  3. The employee then applies for sick leave from the Employee Portal; the stages are used in order and a request that crosses a stage must be split.

7Jameah (Ministry) setup

Jameah is the Ministry's data system. Its agent reads the college's data from read-only database views in the Ministry's format. Medical HRMS creates and maintains these views; this section sets them up and checks them.

7.1 The 23 views

GroupViewsOne row per
Employees (5)jameahEmployeePersonalInfo, …AcademicQualifications, …AcademicExperience, …PreviousExperience, …ProfessionalCertificatesNon-teaching employee of the reported company; table row
Faculty (8)jameahFacultyPersonalInfo, …Research, …AcademicQualification, …AcademicExperience, …PreviousExperience, …ProfessionalCertificates, …Awards, …AttachmentsActive Instructor; table row
Students (10)jameahStudentPersonalInfo, …Companion, …ForeignAddress, …Relatives, …KSAAddress, …HighSchoolCertificate, …Contact, …Scholarship, …AcademicDetails, …AttachmentsStudent; guardian / certificate / document row
  • Codes, not names: lookup columns carry the official Ministry code. A value that is not a valid code for its list is sent empty, never guessed.
  • Teaching staff are sent once, as Faculty, never also as Employees.
  • Column names follow the Ministry document exactly (including its spellings EnglishFourhtName and Summury).

7.3 Jameah Code Map

Some college lists keep their own codes (for example every city has code 90). The Code Map links each college value to the official Ministry code. Rows whose code and name agree with the official list are verified automatically; the others wait for a person.

  1. Open Ministry (Jameah) → Code Map, filter Status = Needs Review.
  2. Open a row, pick the Ministry code, set Status = Verified, save.
  3. Until a row is verified, that value is sent empty.

7.4 Jameah Data Check

The Jameah Data Check page shows what the views would send right now: invalid codes (must be 0), values waiting for a code, settings not filled, mandatory columns with gaps and problems in the source records. Use it after every data change.

7.5 Academic figures

GPA, credit hours and the latest enrolment come from a summary table rebuilt every hour (long queue, about 10 minutes), after every migrate, and with Refresh Academic Figures on the Data Check page. They equal the transcript (the college's official calculation). Only one rebuild runs at a time.

7.6 Verify every view

bench --site <site> execute medical_hrms.jameah.verify.run

Rebuilds every view independently in Python and compares it with the database view value by value. Every line must say OK; it also lists mandatory gaps and invalid codes per view.

7.7 Account for the Ministry agent

bench --site <site> execute medical_hrms.jameah.views.grant_statements

Prints the CREATE USER and GRANT SELECT statements for a read-only account that can read the 23 views and nothing else. Run them as the MariaDB administrator with a strong password, then give the Ministry the host, port, database, user and password.

7.8 Completing staff data

Non-teaching staff (HR Manager): open Ministry (Jameah) → Employees Missing Ministry Data. The report lists every employee the views send with each Ministry-mandatory value still empty.

  1. Download Data Sheet: an Excel sheet with the current values; empty mandatory cells are red and Ministry lists are dropdowns.
  2. HR fills it in.
  3. Check / Import Data Sheet → Check (nothing is saved): a result sheet lists each row's status.
  4. When the check is clean, Import: values are saved through the normal Employee checks.

Teaching staff (existing Instructors without an Employee record): the administrator exports a sheet for HR, HR fills it, then it is checked and imported:

bench --site <site> execute medical_hrms.instructor_data_sheet.export_sheet
# HR fills the sheet and uploads it (Desk > File); check it (nothing is saved):
bench --site <site> execute medical_hrms.instructor_data_sheet.import_sheet --kwargs "{'file': '/private/files/<name>.xlsx'}"
# when the check is clean, import for real:
bench --site <site> execute medical_hrms.instructor_data_sheet.import_sheet --kwargs "{'file': '/private/files/<name>.xlsx', 'commit': 1}"

9Troubleshooting

ProblemWhat to do
"App medical_hrms not in apps.txt"Put each app on its own line in sites/apps.txt (frappe, erpnext, payments, education, hrms, medical_hrms), then install and migrate again.
An employee sees "No leave to apply for yet"They have no annual leave assigned: HR Portal → Leave setup check (section 6.3).
"Failed to decrypt key ... password" in the Error LogEmail Account Notifications: enter the password again and save (section 6.2).
Pages slow for a few minutes every hourThe Jameah academic summary is being rebuilt. Check the Scheduled Job Log (summary.refresh). On the live server, report it if it is noticeable.
An HR user without the Employee role gets "Not permitted" on Employee Self ServiceExpected: that workspace is for employees. HR works from the HR Portal.
Academic hire refused with "College E-mail Needed"Enter the official @alriyada.edu.sa address as Company Email in the Create Employee dialog.
A Ministry column is emptyJameah Data Check: a setting not filled, a Code Map row not verified, or data missing on the record (report / data sheet).
Logo missing on every pageUpload rchs-logo.png again (Website Settings / File).
